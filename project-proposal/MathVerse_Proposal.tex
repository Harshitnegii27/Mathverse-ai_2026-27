\section{Higher-order goal}
This project aims to improve mathematics learning by reducing the gap between a student's actual learning behavior and the support provided by conventional practice systems. While the topic is broader than a single mathematics curriculum, the immediate engineering objective is to translate personalized learning into a measurable, deployable software solution.

\section{Time-to-value}
\begin{itemize}
    \item We will deliver meaningful increments quickly by prototyping the core student workflow and validating the learning experience within a short iteration window.
    \item We will prioritize fast feedback over perfection by implementing the mission flow, question engine, progress tracking, and core AI assistance early.
    \item Success is defined by what can be demonstrated and measured in the first iteration, then improved using student interaction data and feedback.
\end{itemize}

\section{Problem Statement}
\subsection*{Challenges in Traditional Mathematics Learning}
\begin{itemize}
    \item Mathematics practice can become repetitive and demotivating.
    \item The same difficulty is often provided to students with different abilities.
    \item Wrong answers do not always reveal the reason behind the mistake.
    \item Student attention and engagement are difficult to measure.
    \item Teachers and parents have limited visibility into how a student learns.
    \item Previous performance is rarely used effectively to personalize future practice.
\end{itemize}

\noindent\textbf{Why this matters:} A learning platform should respond not only to whether an answer is correct, but also to the student's pace, repeated mistakes, hint usage, and interaction patterns.

\section{Proposed Solution}
\subsection*{Turning Mathematics into an Interactive Mission}
Build a web-based MathVerse AI platform with the following components:
\begin{itemize}
    \item \textbf{Student mission portal:} students select story-based mathematics missions and solve questions through an interactive interface.
    \item \textbf{Gamified question engine:} questions use health, timers, XP, rewards, objectives, and progression to create a mission-oriented experience.
    \item \textbf{AI tutor:} Gwen provides contextual hints, explanations, and mistake analysis using the student's current question and learning history.
    \item \textbf{Adaptive learning engine:} question difficulty is adjusted using performance and behavioral signals.
    \item \textbf{Student memory:} recent attempts and long-term mastery information are stored for personalization.
    \item \textbf{Analytics dashboard:} students, teachers, and parents can view performance, mastery, trends, and engagement indicators.
\end{itemize}

\subsection{Core workflow}
\begin{enumerate}
    \item Student opens the Hero Dashboard and selects a mission.
    \item The system loads questions according to topic, current mastery, and mission difficulty.
    \item Student solves questions while the system records correctness, response time, hint usage, and interaction signals.
    \item Gwen provides guidance when the student requests help or when the system detects a useful intervention point.
    \item The system updates mastery and behavioral memory after each attempt.
    \item The adaptive engine selects an appropriate next difficulty or remediation activity.
    \item Mission results are reflected in the student and parent/teacher dashboards.
\end{enumerate}

\subsection{Operational constraints}
\begin{itemize}
    \item Keep the solution usable on low-to-mid range devices through responsive web design.
    \item Treat eye-tracking as an additional behavioral signal rather than a standalone diagnosis.
    \item Use syllabus-aligned retrieval for AI explanations so generated guidance remains relevant to the curriculum.
    \item Store only the student information required for personalization, progress tracking, and analytics.
\end{itemize}

\section{Solution Approach}
\subsection*{Engineering Focus}
The system focuses on scalable learning workflow, personalization, analytics, and measurable adaptation rather than claiming research-level novelty.

\subsection{Student memory and personalization}
\textbf{Short-term memory:} current mission, recent mistakes, current difficulty, recent hints, and recent response behavior.

\textbf{Long-term memory:} topic mastery, strengths, weaknesses, repeated mistakes, learning patterns, and historical performance.

\subsection{RAG-based AI tutor}
The AI tutor uses Retrieval-Augmented Generation to retrieve relevant syllabus-based material before producing an explanation. The retrieved context can include topic definitions, worked examples, formulas, and approved learning material. This separates curriculum retrieval from response generation and helps keep explanations aligned with the selected topic.

\subsection{LSTM-based time analysis}
An LSTM model analyzes sequences of learning behavior rather than treating each question independently. A representative sequence is:

\begin{center}
Question $\rightarrow$ Response Time $\rightarrow$ Correctness $\rightarrow$ Hint Usage $\rightarrow$ Next Question
\end{center}

The model can learn temporal patterns such as increasing response time, repeated hesitation, changing hint usage, or improvement across successive questions. These signals can complement correctness when deciding whether to continue, remediate, or increase difficulty.

\subsection{Adaptive difficulty}
The adaptive engine combines performance and behavioral signals to select the next activity. For example, sustained high accuracy with efficient response behavior can move the learner from Easy $\rightarrow$ Medium $\rightarrow$ Hard. Repeated errors, high response time, or repeated hint usage can trigger Difficulty $\downarrow$ $\rightarrow$ Remediation $\rightarrow$ Practice $\rightarrow$ Difficulty $\uparrow$.

\subsection{Eye-tracking and engagement analysis}
Eye-tracking can provide non-invasive visual attention signals such as time spent on a question, attention shifts, re-reading behavior, and areas receiving more visual attention. These measurements are treated as complementary evidence alongside answer accuracy, response time, and interaction behavior.

\subsection{Evaluation criteria}
\begin{itemize}
    \item Accuracy improvement across repeated practice sessions.
    \item Reduction in repeated mistakes for identified weak topics.
    \item Change in response time across successive questions.
    \item Hint usage and subsequent correctness.
    \item Engagement indicators such as session completion and interaction consistency.
\end{itemize}

\section{System Architecture}
MathVerse AI follows a layered architecture in which the student-facing application communicates with backend services, persistent student memory, analytics modules, and AI components.

\subsection{Architecture flow}
\begin{center}
\begin{tabular}{c}
\textbf{STUDENT} \\
Mission Interface / Hero Dashboard / Math Battle \\
$\downarrow$ \\[4pt]
\textbf{FRONTEND} \\
Authentication -- Missions -- Questions -- Rewards -- Progress \\
$\downarrow$ \\[4pt]
\textbf{BACKEND API} \\
Users -- Missions -- Attempts -- Progress -- Analytics -- Session Management \\
$\downarrow$ \\[4pt]
\textbf{STUDENT DATA \& MEMORY} \\
Attempts -- Mastery -- Mistakes -- Response Times -- Hint History \\
$\downarrow$ \\[4pt]
\textbf{AI / ANALYTICS LAYER} \\
RAG Tutor -- LSTM Time Analysis -- Adaptive Difficulty -- Engagement Signals \\
$\downarrow$ \\[4pt]
\textbf{DASHBOARDS} \\
Student -- Parent -- Teacher \\
\end{tabular}
\end{center}

\subsection{Data flow}
The student submits an answer $\rightarrow$ the backend records the attempt $\rightarrow$ the analytics layer processes correctness, response time, hint usage, and available behavioral signals $\rightarrow$ student memory is updated $\rightarrow$ the adaptive engine selects the next activity $\rightarrow$ the dashboard reflects the updated learning state.

\subsection{Main components}
\textbf{Frontend:} responsive student interface for missions, questions, battles, rewards, and progress.

\textbf{Backend:} authentication, mission management, question delivery, attempt logging, progress updates, and analytics APIs.

\textbf{Database:} users, questions, curriculum metadata, attempts, mastery records, hint history, mission state, and dashboard metrics.

\textbf{AI layer:} RAG-based tutor, mistake analysis, LSTM-based temporal analysis, and adaptive decision support.

\textbf{Behavioral layer:} eye-tracking and interaction signals used as complementary indicators of attention and difficulty.

\subsection{Parent / Teacher Dashboard}
\begin{itemize}
    \item Overall performance
    \item Topic-wise mastery
    \item Weak areas
    \item Time spent learning
    \item Progress trends
    \item Engagement indicators
    \item Recommended interventions
\end{itemize}

\section{Expected Impact}
The system is designed to provide measurable benefits for each stakeholder in the learning process.

\subsection*{Students}
\begin{itemize}
    \item Higher engagement through mission-based practice.
    \item Personalized learning based on current mastery.
    \item Better conceptual understanding through contextual explanations.
\end{itemize}

\subsection*{Teachers}
\begin{itemize}
    \item Identify weak topics and recurring mistakes.
    \item Track individual progress and learning trends.
    \item Receive actionable insights for intervention.
\end{itemize}

\subsection*{Parents}
\begin{itemize}
    \item Monitor learning progress.
    \item Understand strengths and weaknesses.
    \item View learning patterns rather than only final scores.
\end{itemize}

\section{Scalability}
The platform should scale in both theoretical and practical terms by separating frontend and backend components, using indexed database queries and pagination for common dashboard operations, and keeping backend services stateless where possible.

Operational deployment can use common web hosting, managed databases, containerized or platform-hosted services, and CI/CD for repeatable staging and production releases.

\section{Risks and Mitigations}
\begin{itemize}
    \item \textbf{AI reliability:} ground explanations in syllabus-based retrieval and evaluate generated responses.
    \item \textbf{Privacy:} minimize collected student data and treat eye-tracking information carefully.
    \item \textbf{Model overinterpretation:} use behavioral signals as supporting evidence, not definitive judgments.
    \item \textbf{Evaluation ambiguity:} instrument attempts, timestamps, correctness, and difficulty transitions before testing.
\end{itemize}

\section{Summary}
MathVerse AI proposes a deployable web platform that combines gamification, AI tutoring, student memory, behavioral analysis, and adaptive learning. It focuses on measurable personalization: understanding what the student knows, identifying where the student struggles, and using learning behavior to determine what should happen next.
